# Tauri 2.11、IPC 与窗口权限

本文记录当前 Tauri 2.11 集成方式，以及新增命令、窗口和持久化逻辑时必须遵守的规则。旧的单一 `default.json` Capability 已删除。

## 为什么远程页面需要额外处理

主窗口直接加载 HTTP(S) 阅读网站。Tauri 2.11 对远程 WebView 的自定义命令同时要求：

1. 命令出现在 `generate_handler![]`。
2. `build.rs` 的 AppManifest 注册同名命令。
3. 生成对应 `allow-<command>` permission。
4. 调用窗口的 Capability 包含该 permission。
5. Capability 文件已经列入 `tauri.conf.json`。

缺一项都会出现“命令存在但远程页面 invoke 被 ACL 拒绝”。

项目用 `bun run check:ipc` 自动比对以上来源，并校验远程主窗口没有危险权限。

## Capability 拆分

| 文件 | 窗口 | 用途 |
|---|---|---|
| `main-runtime.json` | `main` | 远程阅读运行时最小权限 |
| `settings.json` | `settings` | 本地设置、插件管理、更新器、创建子窗口 |
| `plugin-editor.json` | `plugin-editor` | 插件编辑、导出和安装 |
| `legal-documents.json` | `privacy`、`terms` | 静态法律文档，仅 core 默认能力 |

`main-runtime` 的远程 URL 范围允许 HTTP(S)，因为可安装插件的站点域名不是构建期固定值；真正的代码与数据范围由 Rust 命令再次验证：

- `get_runtime_plugin` 只返回与当前窗口 URL 唯一匹配的已启用插件。
- 阅读位置命令同时验证窗口 label、当前 URL、请求 URL 和插件 manifest 域名。
- 主窗口不拥有 FS、Shell、Updater、Dialog、Opener、插件管理或窗口创建能力。

保留 `withGlobalTauri: true` 兼容现有页面脚本；安全边界由 Capability 和命令内部校验共同承担。

## 新增命令流程

1. 在 Rust 模块上定义 `#[tauri::command]`。
2. 加入 `src-tauri/src/lib.rs` 的 `generate_handler![]`。
3. 加入 `src-tauri/build.rs` 的 AppManifest 命令数组。
4. 通过构建生成 `src-tauri/permissions/autogenerated/<command>.toml`。
5. 只在确实需要的 Capability 中加入 `allow-<command>`。
6. 若新增 Capability 文件，同步 `tauri.conf.json > app.security.capabilities` 和 `scripts/check-ipc.ts`。
7. 运行完整一致性检查。

```bash
bun run check:ipc
cargo test --manifest-path src-tauri/Cargo.toml --locked
```

不要手工维持一份绕开检查脚本的命令列表；`check:ipc` 会拒绝 handler、manifest、permission 或 Capability 中的残留与遗漏。

## 设置持久化规则

设置格式固定为：

```json
{
  "schemaVersion": 2,
  "_version": 0,
  "global": {},
  "sites": {},
  "pluginConfigs": {}
}
```

写入规则：

- 前端只提交 `patch_settings(expectedVersion, patch)`。
- `SettingsStore` 串行发送 patch，先做乐观 UI 更新。
- 后端版本冲突返回 `Conflict { latest }`，前端刷新后只重试原 patch 一次。
- 第二次仍冲突时采用后端最新文档，不继续无限重试。
- IO 失败会回滚前端乐观状态并向调用者返回错误。
- Rust 所有读写使用同一把进程内锁。
- 临时文件必须与目标同目录；序列化后 flush、`sync_all`，再原子替换，并在 Unix 同步目录。
- 旧 schema、版本不匹配或损坏 JSON 直接覆盖默认设置，不创建备份；插件目录保留并默认启用。
- 插件配置必须写 `pluginConfigs`，不能通过独立文件或旧插件配置命令绕过 Repository。

Rust 原生菜单等内部写入可以调用 `settings::update_setting(app, path, value)`，它使用同一个 Repository、版本递增和事件广播。

## 阅读位置

滚动位置不再存放在 settings 的 Map：

```text
{APP_CONFIG_DIR}/reading-progress/<siteId>/<sha256(url)>.json
```

前端只读写当前 URL 的一个数字，不克隆或重写全部进度。Rust 使用独立锁和原子替换；每站点最多 10,000 个 URL 文件。卸载插件不删除这些文件。

## 缩放、自动翻页和路由铁律

### zoom 由 Rust 控制

- 菜单缩放由 Rust 直接设置 WebView zoom。
- 注入层初始化后调用 `apply_site_zoom(siteId)`。
- 按站点保存到 `sites[siteId].zoom`。
- 前端不要恢复已经删除的通用 `set_zoom` 命令。

### autoFlip 属于 global

`autoFlip` 固定存放在 `global.autoFlip`。关闭窗口、退出应用或离开阅读页时必须把 `active` 清为 false。

自动翻页只更新原生窗口标题，不修改 `document.title`，避免标题 Observer 将倒计时误判成章节切换。

### 启动恢复的两个开关互相独立

- `global.rememberSite`：是否恢复 `global.lastSiteId`。
- `global.lastPage`：是否恢复目标站点的 `sites[siteId].lastReaderUrl`。

离开阅读页时清除该站点的 `lastReaderUrl`；卸载插件不清配置与进度。

## 窗口与 window-state

当前窗口 label：

- `main`
- `settings`
- `plugin-editor`
- `plugin-installer`
- `privacy`
- `terms`

`tauri-plugin-window-state` 不再设置 denylist，因此所有窗口都按 label 分别保存和恢复位置、尺寸和窗口状态。新窗口第一次使用创建时的默认尺寸/居中位置，关闭后下次恢复。

新增窗口时必须：

1. 选择稳定且唯一的 label。
2. 加入且只加入匹配其职责的 Capability。
3. 若需要自定义命令，走完整 IPC 一致性流程。
4. 判断它是可信本地页面还是远程网页，禁止复用过宽权限。

## 编辑菜单（macOS）

### 问题与根因

macOS 应用调用 `app.set_menu(custom_menu)` 后，WKWebView 的 Copy/Paste/Cut/Undo/Redo/Select All 快捷键会全部失效。根因是 macOS 需要应用菜单里存在带 `copy:`/`paste:`/`undo:` 等 selector 的标准「编辑」菜单项，WKWebView 才能响应这些系统级快捷键；自定义菜单覆盖默认菜单后这些项消失了。

这不是 Tauri v2 的 bug，是 macOS 平台行为。Windows/Linux 不受影响。

### 解决方案

用 `PredefinedMenuItem` 创建标准编辑菜单（普通 `MenuItem` 无法绑定系统 selector）。固定六项，带中文 label：

```rust
let edit_menu = Submenu::with_items(app, "编辑", true, &[
    &PredefinedMenuItem::undo(app, Some("撤销"))?,
    &PredefinedMenuItem::redo(app, Some("重做"))?,
    &PredefinedMenuItem::separator(app)?,
    &PredefinedMenuItem::cut(app, Some("剪切"))?,
    &PredefinedMenuItem::copy(app, Some("拷贝"))?,
    &PredefinedMenuItem::paste(app, Some("粘贴"))?,
    &PredefinedMenuItem::select_all(app, Some("全选"))?,
])?;
```

`PredefinedMenuItem` 是必须的——它内部绑定了 macOS 的 `copy:`/`paste:`/`undo:` 等 selector，普通 `MenuItem` 做不到。

### macOS 自动追加的系统项

macOS 会在任何被标记为 Edit 类型的子菜单末尾自动追加：Writing Tools、Auto Fill、Start Dictation…、Emoji & Symbols。这是系统行为，代码无法移除。因为编辑菜单只对编辑器窗口可见，这些项也只在那里出现，不影响壳。

### 动态可见性：remove/insert，不用 set_enabled

macOS 全局菜单所有窗口共享，没有窗口级菜单 API。编辑菜单只在 `plugin-editor` 窗口获得焦点时需要。

- `Submenu::set_enabled(false)` 只是把标题灰掉，不会隐藏整个子菜单，**不能用来实现动态隐藏**。
- 正确做法是 `Menu::remove_at(position)` 移除 + `Menu::insert(item, position)` 重新插入。

实现要点（单一控制点）：

1. `init()` 和 `rebuild_full_menu()` 创建菜单时**不包含** edit_menu。
2. 在 `lib.rs` 的 `RunEvent::WindowEvent` 监听 `Focused`：

```rust
if let tauri::WindowEvent::Focused(focused) = event {
    if focused {
        menu::set_edit_menu_visible(&app_handle, label == "plugin-editor");
    }
}
```

3. `set_edit_menu_visible` 按文本查找「编辑」子菜单，存在则 `remove_at`，不存在则重建并 `insert` 到固定位置。

> 禁止在 `init`/`rebuild_full_menu`/`Focused` 三处都「创建后立即删除」——那是冗余，正确做法是创建时就不放进去，只在 `Focused` 一处按需 insert/remove。

### 禁止复用的错误方案

以下方案在排查过程中踩过坑，记录在此避免重蹈覆辙：

- **用 JS `stopPropagation`/`preventDefault` 拦截**：无效。macOS 菜单 accelerator 是系统级键盘事件，在 JS 拿到事件之前就处理了，DOM 层拦截管不了。
- **删掉阅读器菜单的快捷键**：错误。快捷键是用户日常依赖，绝不能为了「解决编辑器问题」而删除。正确做法是加 Edit 菜单，不是删快捷键。
- **把 Ctrl+C/V/Z 当成菜单 accelerator**：荒谬。系统级快捷键不会被设计成菜单 accelerator，编辑器失效的根因永远不是菜单抢了这些键。

### user-select 与可编辑元素

`body { user-select: none }` 用于防止 UI 文字被选中，但会干扰 `textarea`/`input` 的剪贴板行为。所有可编辑元素必须显式恢复：

```css
input, textarea, select {
    user-select: text;
    -webkit-user-select: text;
}
```

## 更新器

更新行为保持为原生 Rust 后台任务：

- 启动 10 秒后首次静默检查。
- 此后每 24 小时检查一次。
- 正确读取 `global.autoUpdate`。
- 使用 `tauri-plugin-updater` 和 `tauri.conf.json` 中的 GitHub Release endpoints、公钥。
- 后台下载成功后标记待重启，菜单显示“重启并安装”。
- 手动安装或已下载状态调用 `app.restart()`。
- 更新命令只授权本地设置窗口；远程主页面无法调用更新器。

## Windows 快捷键「瞒天过海」方案

### 问题与根因

muda 菜单 accelerator 在 Windows + WebView2 上**全面失效**。WebView2 内嵌的 Edge 引擎在 Win32 菜单消息循环之前消费了所有 Ctrl 系列键盘事件和 F11 等单功能键，菜单 accelerator 收不到任何键盘事件。这不是个别键冲突，是 muda + WebView2 的平台限制。

macOS 不受影响——WKWebView 不拦截这些键，Cmd 系列快捷键走系统级事件处理。

### 解决方案

菜单里**照常显示快捷键提示文字**（accelerator 参数照常传 `CmdOrCtrl+X`，Windows 上这个字符串只用于显示），实际触发改为**前端 keydown 监听**：

1. `menu.rs` 提取 `pub fn handle_menu_action(app, id)` 为公共函数，包含所有可触发的菜单动作。
2. `commands.rs` 新增 `simulate_menu_click(action)` 命令，调 `handle_menu_action`。
3. 前端 `inject.ts` 在 capture 阶段监听 keydown，匹配 Ctrl+X 或 F11 后 `preventDefault` + `stopImmediatePropagation` 拦住 WebView2 默认行为，再 `invoke('simulate_menu_click', { action })`。
4. `isWindows` 判断（`navigator.userAgent.includes('Windows')`）保证 macOS 完全不进入此分支。

用户看到的菜单和 macOS 一样有快捷键提示，功能也能正常工作——「瞒天过海」。

### 菜单栏隐藏（Ctrl+H，Windows 专属）

Windows 上菜单栏嵌入窗口顶部，不像 macOS 在系统顶部菜单栏。`Ctrl+H` 隐藏/恢复菜单栏（`win.hide_menu()` / `win.show_menu()`）。

- accelerator 绑 `None`，菜单文字用 `\t` 手写 `Ctrl+H` 提示（`MenuItem::with_id(handle, "toggle_menu", "隐藏菜单\tCtrl+H", true, None::<&str>)?`）。
- 前端 keydown 唯一触发路径，避免 accelerator + keydown 双重触发。
- 全屏自动隐藏菜单时必须调 `sync_menu_hidden_for_fullscreen(true/false)` 同步原子状态，否则 Ctrl+H 需要按两次才能恢复。

## 摸鱼键与全局热键

### 摸鱼键（Cmd/Ctrl + `）

隐藏窗口再恢复。用 `tauri-plugin-global-shortcut` 注册全局热键（不是菜单 accelerator），窗口隐藏后仍可响应——窗口内 keydown 监听在 `win.hide()` 后失效，全局热键是唯一可靠方案。

```rust
#[cfg(target_os = "macos")]
let mod_key = Modifiers::SUPER;
#[cfg(not(target_os = "macos"))]
let mod_key = Modifiers::CONTROL;
let stealth_key = Shortcut::new(Some(mod_key), Code::Backquote);
```

- macOS：Cmd+`，首次使用需授权辅助功能权限。
- Windows：Ctrl+`，同时隐藏任务栏图标（`set_skip_taskbar(true)`）。
- 菜单里显示「摸鱼」项，accelerator 绑 `CmdOrCtrl+\`` 用于显示提示。全局热键和菜单 accelerator 不会重复触发——macOS 上全局热键优先，Windows 上菜单 accelerator 被 WebView2 吃掉不生效。
- `STEALTH_ACTIVE` 原子状态保证幂等。

### 书店快捷键（Ctrl+1~7，跨平台）

前端 keydown 监听，不走菜单 accelerator。序号 1-based 映射：1=微信读书，2=第一个插件站点，依此类推。8/9/0 被其他快捷键占用（隐藏光标/阅读变宽/实际大小），书店快捷键只用 1~7。

## 平台条件编译注意

### `RunEvent::Opened` 是 macOS 专有变体

`tauri::RunEvent::Opened { urls }` 对应 macOS 的 `application:openURLs:` 文件关联机制。**Windows/Linux 上这个枚举变体不存在**，直接编译报错 `no variant named Opened found for enum RunEvent`。必须 `#[cfg(target_os = "macos")]` 门控。

Windows/Linux 的 `.atrd` 文件关联走 `tauri-plugin-single-instance` 的 `args` 回调，不依赖 `Opened`。

```rust
#[cfg(target_os = "macos")]
tauri::RunEvent::Opened { urls } => {
    plugin_installer::handle_opened_urls(app_handle, &urls);
}
_ => {}
```

### `tauri-plugin-dialog` 2.7.2+ 的 MessageDialogResult 类型变更

`blocking_show_with_result()` 的返回类型从 `bool` 变成了 `MessageDialogResult` 枚举。不能再用 `!` 取反，需要用 `!= MessageDialogResult::Ok` 判断。

```rust
// ❌ 旧写法（dialog 2.4.x）
if !confirmed { return Err("用户取消".to_string()); }

// ✅ 新写法（dialog 2.7.2+）
if confirmed != tauri_plugin_dialog::MessageDialogResult::Ok {
    return Err("用户取消".to_string());
}
```

## NSIS 安装包配置

### 安装程序图标

默认 NSIS 用 Tauri 的蓝色 logo。在 `tauri.conf.json` 的 `windows.nsis` 里配置：

```json
"nsis": {
  "installerIcon": "icons/icon.ico",
  "languages": ["SimpChinese", "English"]
}
```

### 多语言

`languages` 数组控制 NSIS 安装界面语言。第一个是默认语言（中文 Windows 上自动选中）。当前配置为简体中文 + 英文。

### Windows ARM64 构建

两个 NSIS job 并行构建，完全对称：

| Job | Runner | Target | Stage 脚本 |
|-----|--------|--------|-----------|
| `windows-nsis-x64` | `windows-2025` | `x86_64-pc-windows-msvc` | `STAGE_TARGET=x86_64-pc-windows-msvc` |
| `windows-nsis-arm64` | `windows-11-arm` | `aarch64-pc-windows-msvc` | `STAGE_TARGET=aarch64-pc-windows-msvc` |

`scripts/stage-windows-release.ts` 通过 `STAGE_TARGET` 环境变量参数化，自动选择架构标识和输出文件名。两个架构产出完全对称的文件集：标准化 exe + `.sig` + SHA256SUMS + release-info.json。

## 发布资产命名规范

所有平台的安装包文件名统一为 `{appId}-{version}-{platform}-{arch}-setup.{ext}` 格式：

| 平台 | 文件名模式 |
|------|----------|
| macOS Apple Silicon | `weixin-reader-{ver}-macos-aarch64.dmg` |
| macOS Intel | `weixin-reader-{ver}-macos-x86_64.dmg` |
| Windows x64 | `weixin-reader-{ver}-windows-x86_64-setup.exe` |
| Windows ARM64 | `weixin-reader-{ver}-windows-aarch64-setup.exe` |

macOS 资产在 `release.ts` 的 `macTargets` 里定义，`arch` 字段驱动文件名生成。Windows 资产在 `stage-windows-release.ts` 里参数化生成。`latest.json` 的平台 key（`darwin-aarch64` 等）是 Tauri updater 协议的标准标识，不能改。

## 日志与性能

- 日志单文件最大 2 MiB，`KeepSome(2)` 表示活动文件加最多两份轮转文件，总计最多三份。
- 启动时不做同步 TCP 网络探测，避免阻塞首屏。
- Fanqie 五秒诊断线程已删除。
- 前端性能探针每页只采样一次；错误监听器在采样后移除，最慢资源只维护前五名。
