# Tauri 2.11 升级踩坑记录

> 本文档记录从 Tauri 2.9 升级到 2.11 过程中遇到的三个关键问题及解决方案，
> 供后续开发者参考，避免重复踩坑。

---

## 一、远程页面 invoke 全部失效（ACL 权限）

### 问题现象

升级到 Tauri 2.11 后，**所有从远程页面（如 `weread.qq.com`）发起的 `invoke` 调用全部被静默拒绝**——没有报错、没有日志，调用直接被丢弃。表现为：

- 窗口标题不跟随页面变化（永远显示"艾特阅读"）
- 自动翻页倒计时不显示
- `log_frontend` 命令不输出到终端
- 缩放、书店切换等菜单功能异常

**但本地页面**（`tauri://localhost`，如设置窗口）的 invoke 一切正常。

### 根因

Tauri 2.11 新增了 ACL 安全检查（`src/webview/mod.rs`）：

```rust
// 当请求来自非本地（远程）来源时，如果 ACL 没有为该命令配置权限，直接 reject
if (plugin_command.is_some() || has_app_acl_manifest || !is_local)
    && invoke.acl.is_none()
{
    invoke.resolver.reject(...);
    return;
}
```

旧版本（2.9）对远程页面的 invoke 不做 ACL 检查，自定义命令可以直接调用。
2.11 开始，远程 URL 的每个 invoke 都必须有对应的 ACL 权限授权。

### 解决方案（两步缺一不可）

#### 第 1 步：build.rs 注册 AppManifest

在 [build.rs](../src-tauri/build.rs) 中声明所有自定义命令：

```rust
tauri_build::try_build(
    tauri_build::Attributes::new()
        .app_manifest(tauri_build::AppManifest::new().commands(&[
            "log_frontend",
            "set_title",
            "save_settings",
            // ... 所有自定义命令
        ])),
)
```

这一步会在 `permissions/autogenerated/` 下生成权限定义文件
（如 `allow-set-title.toml`、`allow-log-frontend.toml`）。

#### 第 2 步：capabilities/default.json 声明权限

在 [capabilities/default.json](../src-tauri/capabilities/default.json) 的 `permissions` 数组中，
显式声明每个命令的 `allow-*` 权限：

```json
{
  "permissions": [
    "core:default",
    "allow-set-title",
    "allow-log-frontend",
    "allow-get-app-name",
    // ... 所有命令的 allow-* 权限
  ]
}
```

> **注意**：权限标识符用 **hyphen**（`allow-set-title`），
> 不是 underscore（`allow-set_title`）。
> 命令名里的下划线会自动转换为 hyphen。

### 诊断方法

如果远程页面 invoke 不工作但本地页面正常：

1. 检查 `permissions/autogenerated/` 下是否有对应命令的 `.toml` 文件
2. 检查 `capabilities/default.json` 的 `permissions` 是否包含 `allow-xxx`
3. 在 Rust 命令里加文件日志（`/tmp/atreader-debug.log`），排除 stdout 被吞的问题：
   ```rust
   let _ = std::fs::OpenOptions::new()
       .create(true).append(true)
       .open("/tmp/atreader-debug.log")
       .and_then(|mut f| std::io::Write::write_all(&mut f, msg.as_bytes()));
   ```

### 新增命令时的检查清单

每次在 `invoke_handler` 中新增 `#[tauri::command]` 时，必须同步完成：

- [ ] 把命令名加入 `build.rs` 的 `AppManifest::commands` 列表
- [ ] 把 `allow-xxx`（hyphen 格式）加入 `capabilities/default.json`
- [ ] 远程页面 + 本地页面各测试一次

> **重要**：`build.rs` 和 `capabilities/default.json` 里的命令列表必须与
> `lib.rs` 的 `invoke_handler` **完全对齐**。曾经因为遗漏了 `get_settings`、
> `save_settings` 等命令，导致远程页面的配置文件写不进去、缩放和阅读进度永远不保存。
> 建议每次发版前用以下命令做一次全量对比：
> ```bash
> # 从 lib.rs 提取 invoke_handler 里的所有命令
> grep -oP 'commands::\K\w+|settings::\K\w+|update::\K\w+' src-tauri/src/lib.rs | sort
> # 从 build.rs 提取 AppManifest 里注册的命令
> grep -oP '"\K[\w_]+' src-tauri/build.rs | sort
> ```
> 两者必须完全一致（差集为空）。

## 二、WebView 默认缩放异常

### 问题现象

升级到 Tauri 2.11 / wry 0.55 后，窗口启动时视图巨大（约 200%），
且菜单的放大/缩小/恢复大小不响应。

### 根因

wry 0.55 改变了 WKWebView 的默认缩放行为——窗口创建后默认 zoom 不再是 1.0。

### 解决方案

**初始缩放**：在 [lib.rs](../src-tauri/src/lib.rs) 窗口创建后，立即从设置文件
读取用户保存的 zoom 值并应用：

```rust
let win = builder.build()?;

// Tauri 2.11/wry 0.55 需要在窗口创建后主动设置初始缩放
let settings = settings::get_settings(app.handle().clone());
let zoom = settings.get("global")
    .and_then(|g| g.get("zoom"))
    .and_then(|z| z.as_f64())
    .unwrap_or(0.75);
let _ = win.set_zoom(zoom);
```

**菜单缩放**：在 [menu.rs](../src-tauri/src/menu.rs) 的 `on_menu_event` 中
直接处理 zoom_in/out/reset，不依赖前端 invoke 转发：

```rust
"zoom_in" => {
    let current = get_current_zoom(app);
    let next = next_zoom_level(current, true);
    let _ = win.set_zoom(next);
    save_zoom(app, next);
    let _ = win.emit("show-toast", format!("{}%", (next * 100.0) as i32));
}
```

## 三、自动翻页与 Title 监控的交互缺陷

### 问题现象

自动翻页的倒计时每秒修改 `document.title`，
导致窗口标题监控的 MutationObserver 每秒误触发一次"章节切换"事件，
干扰翻页动作，最终表现为：**倒计时在走，但翻不了页**。

### 根因

原有代码用 `document.title` 来显示倒计时：

```typescript
// 旧代码（有问题）
document.title = `${this.appName} - 自动翻页 - ${this.countdown} 秒`;
```

这会触发 IPCManager 的 title MutationObserver → `checkRouteHandler()` →
检测到 `titleChanged = true` → 触发假"章节切换"事件 → 干扰翻页。

### 解决方案

自动翻页**完全不碰 `document.title`**，
改用 `invoke('set_title')` 直接更新 macOS 原生窗口标题栏：

```typescript
// 新代码（修复后）
invoke('set_title', { title: `${this.appName} - 自动翻页 - ${this.countdown} 秒` });
```

`document.title` 始终保持真实页面标题，MutationObserver 只在真实页面/章节变化时触发，
倒计时不再产生假事件。

## 四、新增窗口的 invoke 权限丢失

### 问题现象

插件编辑器窗口（`plugin-editor`）打开后，编辑器里所有字段为空，
无法加载插件配置。控制台无报错。

### 根因

Tauri 2.11 的 ACL 权限检查不仅针对命令，还针对窗口。
`capabilities/default.json` 的 `windows` 数组必须显式列出所有需要 invoke 权限的窗口。

旧版本（2.9）不检查窗口是否注册，所有窗口默认有权限。
2.11 开始，未注册到 `windows` 数组的窗口，invoke 会被静默拒绝（无报错）。

### 解决方案

在 `src-tauri/capabilities/default.json` 的 `windows` 数组中添加新窗口：

```json
{
  "windows": ["main", "settings", "privacy", "terms", "plugin-editor"]
}
```

### 诊断方法

如果某个窗口的 invoke 不工作（无报错、无日志），检查：

1. 该窗口的 label 是否在 `capabilities/default.json` 的 `windows` 数组中
2. 如果不在，添加后重新编译

## 开发铁律

> 以下规则由实际踩坑总结，违反任何一条都会导致难以排查的 bug。
> 新增代码、修改代码时必须逐条检查。

### 铁律 1：新增自定义命令必须三处同步

在 `invoke_handler` 中新增 `#[tauri::command]` 时，必须同步：

1. `src-tauri/build.rs` 的 `AppManifest::commands` 列表
2. `src-tauri/capabilities/default.json` 的 `permissions` 数组（`allow-xxx`，hyphen 格式）
3. `src-tauri/src/lib.rs` 的 `generate_handler!` 宏

三处的命令列表必须完全一致。遗漏任何一处，远程页面的 invoke 会被静默拒绝（无报错日志）。

验证方法：
```bash
grep -oP 'commands::\K\w+|settings::\K\w+|update::\K\w+' src-tauri/src/lib.rs | sort > /tmp/cmds_lib.txt
grep -oP '"\K[\w_]+' src-tauri/build.rs | sort > /tmp/cmds_build.txt
diff /tmp/cmds_lib.txt /tmp/cmds_build.txt  # 差集必须为空
```

### 铁律 2：save_settings 必须深度合并，禁止浅层覆盖

`src-tauri/src/settings.rs` 的 `save_settings` 对 `global` 和 `sites` 做递归深度合并。

**禁止**把深度合并改回浅层 `obj.insert(key, value)`——那会导致 partial update 覆盖整个对象，丢失其他字段（如切书店丢 zoom、调缩放丢 rememberSite）。

### 铁律 3：Rust 端写入配置必须走 update_setting，禁止手搓 JSON

Rust 端所有配置写入必须通过 `settings::update_setting(app, path, value)`，禁止直接构造 `json!({ "global": { ... } })` 调 `save_settings`。原因：

- `update_setting` 自动递增版本号，参与乐观锁
- `update_setting` 写入后 emit `settings-updated` 通知前端 reload
- 手搓 JSON 传 `version: None` 会绕过版本控制，覆盖前端更新的数据

### 铁律 4：zoom 由 Rust 端统一控制，前端禁止调 set_zoom

zoom 按站点独立存储（`sites[siteId].zoom`）。控制权完全在 Rust 端：

- **菜单缩放**：Rust 端 `menu.rs` 读写 `sites[siteId].zoom` + `win.set_zoom()`
- **书店切换**：前端注入脚本初始化时调 `invoke('apply_site_zoom', { siteId })`
- **启动**：Rust 端 `lib.rs` 从 `sites[lastSiteId].zoom` 读取

**禁止**在前端 `settingsStore.subscribe` 或 `syncMenuState` 中调 `invoke('set_zoom')`——注入脚本的 `siteContext.siteId` 在导航后可能还是旧值，会用旧站点的 zoom 覆盖新站点。

### 铁律 5：autoFlip 是全局配置，不是站点配置

`autoFlip`（active/interval/keepAwake）存放在 `global`，不在 `sites[siteId]`。
前端写入用 `updateGlobal({ autoFlip: ... })`，**禁止**用 `updateSite(siteId, { autoFlip: ... })`。

### 铁律 6：lastReaderUrl 在离开阅读页时必须清除

`handleLastPageSaving` 中：
- 在阅读页 → 写入当前 URL
- 离开阅读页（返回首页）→ 清除为 `null`

不清除会导致：用户返回首页后切换书店再切回，被错误地跳回书里。

### 铁律 7：禁止用固定延迟解决状态同步问题

**禁止**用 `setTimeout(fn, 500)` 或 `std::thread::sleep(Duration::from_millis(500))` 等待页面加载、UI 就绪或事件完成。必须使用事件驱动：

- 页面加载完成 → 注入脚本初始化 → 调用 Rust 命令
- Rust 端需要通知前端 → `app.emit("event", payload)`
- 前端需要通知 Rust 端 → `invoke('command', args)`

固定延迟是不可靠的——不同设备、网络条件下所需时间不同，会导致竞态或无响应。

### 铁律 8：自动翻页禁止修改 document.title

自动翻页的倒计时显示用 `invoke('set_title')` 直接更新原生窗口标题栏，**禁止**修改 `document.title`。

修改 `document.title` 会触发 MutationObserver，被误判为章节切换，干扰翻页动作。

### 铁律 9：新增窗口必须同步注册到 capabilities/windows

在 Rust 或前端创建新窗口（`WebviewWindow::builder` 或 `new WebviewWindow`）时，必须同步：

1. `src-tauri/capabilities/default.json` 的 `windows` 数组

遗漏会导致该窗口的所有 invoke 被静默拒绝（无报错日志）。

验证方法：
```bash
# 从 Rust 代码提取所有窗口 label
grep -oP 'WebviewWindow::builder\(app, "\K[^"]+' src-tauri/src/*.rs
# 从前端代码提取
grep -oP "new WebviewWindow\('\K[^']+" src/windows/*.html
# 对比 capabilities/default.json 的 windows 数组
```

当前已注册窗口：`main`、`settings`、`privacy`、`terms`、`plugin-editor`。
